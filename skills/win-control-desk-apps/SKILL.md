# 应用接入

使用项目自带的 `tools/manage_apps.py` 发现实例、预览计划并通过本机 API 保存。不另写配置导入器，不直接覆盖运行中的 `config.json`。配置保存与实际启动、退出验证分别报告。

## 找到正确的项目和实例

- 从用户打开或明确指定的源码目录确认 `server.py`、`tools/manage_apps.py`、`ops_model.py`。Skill 的安装目录不一定是源码目录；以下相对路径和命令都以源码根目录为基准。无法确定项目时询问路径，不全盘搜索。
- 使用已安装的 Python 3.12+；以下 `python` 代表已核实的解释器，Windows 也可用 `py -3.12`。此卡片发现流程面向 Windows，不把 macOS 兼容入口当作已支持的同一流程。
- 从用户使用的页面或启动日志确定 URL，只连接 `http://127.0.0.1:实际端口`。默认从 9600 起选端口，不把 9600 当作当前必然值。
- 读取 `/api/state` 时只保留目标所需信息，核对 `consoleCwd`、`dataDir`、`logsDir`、`version`、`platform` 和采集新鲜度。`consoleCwd` 必须指向该源码目录，`version=demo` 不可写入；工具会拒绝目录不符、演示服务或尚未就绪的采集，不绕过检查。
- 默认配置位于 `%APPDATA%\总控台`，日志位于 `%LOCALAPPDATA%\总控台\Logs`；环境变量或可选启动器可改变位置，以运行状态为准，不假设项目的 `data/` 是正式配置。
- 未启动时按该项目 README 使用 `start.bat` 或用户既有入口。只要求配置卡片不代表可以停掉另一份总控台、换数据目录或重新启动个人应用。

## 发现与配置

1. 从项目根目录发现指定应用；将示例端口替换为已核实的端口：

   ```powershell
   python tools/manage_apps.py --url http://127.0.0.1:9600 discover "应用名"
   ```

   根据返回的 PID、创建时间、EXE、端口、窗口及已有卡片确定目标。有同名卡片时用 `appId` 更新；多个独立候选会改变控制对象时才请用户选择。只在用户要求批量接入时省略过滤词。

2. 查明实际启动命令和相关位置。优先用户指定入口、应用快捷方式、目标进程给出的目录和该应用的安装信息。解释器、服务和终端需要实际脚本入口及有效参数；不以 `python.exe`、终端宿主或端口号代替应用身份。路径和文件存在才添加，不输出全机命令行或凭据。

3. 按 [卡片计划与关闭方式](references/card-plan.md) 生成 UTF-8 JSON，放在项目忽略的 `tmp/` 中。没有可靠启动方式时保留空命令的观察卡片并说明限制；不要猜测启动或退出参数。

4. 先预览，再按用户授权写入：

   ```powershell
   python tools/manage_apps.py --url http://127.0.0.1:9600 apply tmp/add-app.json
   python tools/manage_apps.py --url http://127.0.0.1:9600 apply tmp/add-app.json --write
   ```

   用户已要求添加/配置时，预览符合目标后完成写入；用户明确要求“先展示方案”时先展示，不写入。工具会在实际数据目录保存 `config.before-apps-*.json` 备份。批量写入不是跨卡事务，失败时核对已完成项和当前状态，仅修正剩余项，不无限重试或自行回滚。

5. 默认用只读 `verify` 核对位置、窗口和启动配置；该命令不会试启停应用：

   ```powershell
   python tools/manage_apps.py --url http://127.0.0.1:9600 verify
   ```

   用户要求自行验收或不做中期检查时尊重该范围。PID/窗口已变化就重新发现；不能放宽身份校验让计划通过。

## 保留的边界

- 普通配置任务不点击启动、停止、重启、强制结束或业务按钮。用户另外要求实测时，先明确目标与动作，再按授权执行；关闭文档或中断任务所需确认不能省略。
- 运行中修改 `command/cwd/port/kind/shell` 会被拒绝。保留拒绝结果，不用停止应用或绕过 API 的方式完成配置。
- 窗口绑定不等于进程归属。共享终端只关联用户选定的宿主窗口，不把整个终端、其他标签页、普通浏览器或 PWA 认作服务子进程。
- 身份规则由后端采集，保留当前用户、PID/创建时间、完整 EXE、脚本参数及独立子卡片边界。不手写 `instanceMatch`，不按名称或端口批量认领、终止。
- 未涉及的动作和布局保留，沿用稳定动作 ID。不要为追求默认布局补回用户明确删除的按钮；窗口操作仅支持前台与关联，不配置置顶按钮。

交付实际新增/更新的卡片、关闭方式、只读核对结果和未验证项。计划、备份、个人图标及真实截图留在用户本机，不随项目提交。
